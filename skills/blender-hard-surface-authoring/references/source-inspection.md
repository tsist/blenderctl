# G1：审阅实际完整 L0

## 证据来源

从当前保存候选读取真实未求值 mesh，记录文件/对象身份、数据块、变换与修改器状态。区分实际源线、贴面编辑笼、求值线和渲染三角线。SVG 可提高可读性，但必须从本次真实网格及边/面 ID 导出，不能用设计草图或手画叠线充当实际证据。

宿主生成的轴对齐提案或示意网格不构成 Blender 实际证据。新实现经当前项目准确批准后，独立加载对应实现、构造并保存新候选，在独立 Blender 进程/新读取上下文重开后导出实际 L0；旧实现的执行许可与旧候选的 G1 接受均不覆盖新版本。新布局需清楚呈现宽阔平面的直线条带、角部局部扇形及其最差面角，而不只展示外观近似的总览。

优先一个不依赖 Cycles 的只读检查单元。工具只能导出统计时，声明缺少哪种可读图或对应关系；不能宣称完整 G1 已通过。当前入口与字段从[工作单元](work-units.md)查询。

## 必须看见什么

1. 全件无遮挡源线框：正面、背面和足以核查厚度/孔壁的角度；必要时隔离隐藏面
2. 区域隔离：孔入口、孔出口、内壁、外缘支撑、圆角转接、外侧面带、底面与所有接缝
3. 对照表：实际顶点/边/面 ID、语义区域/端口、环/条带、极点价数和每个区域的面数
4. 拓扑事实：面型、法向朝向、边关联、流形/边界、连通、退化和自交；分开记录纯图与三维检查
5. 编辑解释：规则 loop 与过极点闭合链分开，指出选环/滑动/插线通路与限制

没有背面或孔出口、顶面计数冒充总面数、只有评估后线框、只给 quads 百分比，都属于关键覆盖缺失。

## 如何出结论

逐项指出证据、结果和最小失败对象。面数少但环职责不清、结构合规但极点堵住预定编辑、全件密度被局部峰值掩盖，均需回到结构规划。不要先在失败结构上调 SubD 或灯光。

向用户展示本次真实全件与关键区域，附短结构账和待解决问题。**在用户接受该源笼结构前停住所有依赖它的形体拟合与高光优化**；可以继续不依赖其批准的只读分析或接口工作。G1 接受必须对应当前候选身份，不借用旧模型的接受记录。

输出：实际网格数据/可读图引用、分区账、明确的 loops/strips 与局限、技术结果、用户结构审阅状态、下一关输入。缺少审阅不是技术失败，但也不是已批准继续。

## 完整预检必须阻止后续执行

在新候选冻结及原生申请前，为基线和预定的独立编辑/插线状态列出完整清单。每一状态都要检查全件所有面：顶面、底面、孔壁、圆角和侧壁；作者双精度坐标及精确 float32 存储预测均使用相同门限。把每个必需项按 AND 汇总，缺失、失败或未测一项就不能声明项目预检通过。

每个状态绑定其预先声明的参数和网格校验值，不能重复使用一份通过报告填满多个标签。保留每状态原始报告及开始/结束实现指纹，独立核对摘要与原始 gate、finding、区域极值一致。中性单元测试总数只证明其自身覆盖，不能取代当前工程实参的整件门槛。HOST 预测通过后仍需独立原生检查；二者不能互相冒名。

工程矩阵、单元回归和图形输出分别使用独立执行目录。矩阵开始前核对源文件白名单，运行中不得与其他测试共用源树；结束时同时核对源码和驱动指纹。发现额外测试产物或漂移时保留原失败结果，先解释并修复隔离，不直接把总结果改成通过。
