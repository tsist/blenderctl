# 骨架质检、无皮肤运动与配对匹配

新建角色、调整骨位或改动约束驱动后，先走完这一份骨架质检流程并取得双审通过回执，再进入任何蒙皮、转权或修权步骤。把骨架关口守严，后面蒙皮可以省下大量返工。

## 固定顺序：先解剖，后全向图，再无皮肤运动

1. **核对真实解剖映射**：列出角色物种的关键真实关节与数字骨骼的对应关系（如人形 SC/AC/GH、四足肩胛与跗膝），确认内部关节中心、骨链连接与局部弯曲平面。参考外轮廓与截面辅助定位，用真实骨骼与网格叠图验证占位。
2. **分配稳定分区颜色**：按躯干、头颈、左/右上肢、左/右下肢、尾与附属链设定固定颜色映射并附图例，确保左右侧凭颜色一眼分辨。同时核对 Data Bone 与 Pose Bone 实际颜色一致。
3. **输出 9 宫格或 16 宫格叠图**：基于静置（Rest）姿态渲染正、背、左、右、顶、底加斜向全向图，关节密集区（肩带、骨盆、手爪、面部）另补局部近景。每组配套「网格实面叠骨图」与「独立骨骼轴向图」，画幅按全部显示几何顶点计算，保证每根骨头清晰可读。
4. **验证无皮肤运动**：不挂皮肤，逐项测试角色用途要求的动作：
   - 相关关节 FK 屈伸、外展与轴向旋转。
   - 肩胛/肩带与骨盆协同运动（验证动作方向符合真实解剖，如验证肩胛下角外摆与关节盂朝上，同时观察上臂与肩带组合）。
   - IK 弯曲平面、极向（Pole）轨道、近伸展稳定度、手脚支撑与可达极限。
   - 关键帧、中间过渡帧、左右对称与一键回静置中立姿态。
5. **留存完整通道与求值证据**：每组测试态记录帧/子帧、旋转模式、location/rotation/scale、`matrix_basis`、自定义属性，以及实际求值后的全部变形骨矩阵、头尾长度和 B-Bone 各段矩阵（`world_pose @ pb.bbone_segment_matrix(i, rest=False)`）。同时用原生 Action `frame_set` 与脱离 Action 的真实通道分别做独立冷开重放，验证中立状态和返回结果一致。
6. **主审与独审签认回执**：主制作与独立审查员实际看完所有多向图、近景与运动证据，形成限定角色、骨架结构、参照和运动范围的通过回执，随后摆出代表姿态完成用户审看①。

### 结构改动后的复验与复用规则

- **忠实复用 Armature 数据块**：保留已有作者骨位和 Roll 时，优先复制原 Armature 数据块并在复制后核对完整矩阵、长度、父链、连接与 B-Bone 段；新增或修改 EditBone 时先写非零 head/tail，再赋 matrix 与 length，退出编辑模式后核查真实 DataBone。
- **区分中立基线与动作回放**：生成新骨架后立即保存原生中立基线；在 Pose 模式下验证控制切换与回中立，以原物理 Rest 探针（含 B-Bone 段混合）作为绝对基准。
- **改动即重审受影响范围**：一旦修改骨位、Roll、父链、约束、驱动或 IK 设置，重新执行受影响区域的叠图与运动验收并更新回执。只调整证据格式且物理骨架、Action、参照完全一致时，可做不变桥接并明确引用既有主独审记录。
- **独立尾巴连接方向**：使用 Rigify 尾巴组件时，`connect_chain` 表示共享父链 B-Bone 端点；当真实尾根与简化骨盆有偏置时，改用独立父连尾链保留真实尾根，并按实际连接方向校验变形骨朝向。

## 四足四段爪：禁伸缩与支撑核查

制作犬猫/羊兔等四足四段爪骨架时，**优先通过自研 `rigging_workflow` v003 的 `modular_rig.prepare_reference(kind='QUADRUPED')` → `modular_positioning` → `confirm_reference` → `generate` 流程生成**（其底层由插件合规调用 Rigify `limbs.front_paw` / `limbs.rear_paw`，自动锁定 `segments=1, bbones=1` 并写入 `rigging_modular_v1` 元数据与 `modular_neutral` 中立基线），不要绕开自研封装直接手写裸 Rigify 脚本。生成后重点核查下面四件事：

1. **逐链关闭真实伸缩**：除了把主控制 `IK_Stretch` 滑杆设为 0，还要逐一检查主链、IK2、IK3 上每条 IK 约束的 `use_stretch` 以及链上 PoseBone 的 `ik_stretch`。确认真实消费分支后，再逐态核验长骨 DEF 长度和弯曲平面。
2. **把刚性长骨与弹性脊柱分开看**：脊柱变形骨常通过 `STRETCH_TO` 连接相邻 tweak，骨盆横移带来微小拉伸属于设计预期；验收时把四肢刚性长骨的定长指标与脊柱弹性段分开统计。
3. **以真实趾端与 Socket 验支撑**：身体重心下压或改变 Pole 弯曲平面时，掌跖段联动会带动腕/踝自然位移，应以主爪控制器、Toe Socket 以及趾骨 DEF 头尾的世界轨迹作为支撑判据；同时记录每个启用 IK 约束对真实目标（按 constraint 的 `target`/`subtarget`/`use_tail`）的残差，区分“目标超出链长”与“支撑滑动”。
4. **双控制轴转与四段爪手动对齐**：上段 DEF 若通过首 tweak 跟随肩胯，做 FK 轴转测试时配合对应 `upper_arm_tweak` / `thigh_tweak` 绕自身长轴旋转并检查非目标骨无联动。四段爪做 IK→FK 首次切换时，先记录切换前四根 DEF 的世界矩阵，切到 FK 后顺序写入三段 FK 控制和独立 Toe 控制的姿态矩阵，每步更新依赖图，并如实报告首次匹配的端点距离与旋转残差。

## 自包含人形：短命 FK/IK 配对匹配

在自包含 Rigify 人形骨架的静置与无动画姿态调试中，连续反复跑原生 FK/IK Snap 容易因方向搜索步长与单轴 IK 约束带来累积漂移。采用同核短命配对（`PoseMatchPair`）可以避免同一操作内的递推漂移：

1. **先查真实消费链**：匹配前后统一检查最终消费的 DEF 矩阵、局部轴和 B-Bone 段，把「首次有限残差」「反复切换累积差」「保存冷开重放差」三项分开记录。
2. **首次切换做有界细化与远端 Roll 保留**：首次 FK→IK 在原生匹配后，对基部 Y 方向做小范围细化（`refine_base_direction`），再从真实目标 DEF 世界旋转分离局部 Y 轴扭转，追加到 `forearm_tweak` / `shin_tweak` 的 Y 通道（`preserve_distal_roll`），保住原有 Roll、位置与缩放。首次 IK→FK 走原生 Generic Snap 并记录首次残差。
3. **同操作内一致恢复**：配对实例在内存中保存全骨架输入通道、自定义属性、完整上下文（帧/子帧、世界、Armature Data、父对象与父逆矩阵、IK Solver）及配置指纹。同一操作再次切换且全部状态一致时，直接恢复已存对端（`paired_restore`），避免把近似解重复喂回求解器。
4. **编辑即失效并保护 AutoKey**：一旦用户编辑任意控制、改约束驱动、切帧或挂载 Action/NLA，旧配对自动失效并重新匹配；匹配期间临时关闭 AutoKey 并在 `finally` 块恢复原值，异常时回滚全部真实输入。结束操作后调用 `close()` 释放短命实例。
5. **保留新父链增量复验**：新增肩胛载体等非 DEF 控制骨后，补做肩胛/锁骨非中立下的上肢配对、原生 Pole 与 IK 父级切换，确认多次往返 FK 精确回归且 IK 首次残差稳定。

## 工作副本与会话运行习惯

- 磁盘上的骨架生成、镜像、定位与校验优先走 `blenderctl.ps1` 公共入口，在独立工作副本上推进；需要现场视口查看定位骨或焦点时，走对应插件的现场会话入口。
- 每轮作业结束及时清理本任务不再使用的后台 Blender 实例，核实进程归属后再结束自有进程，保护用户正在使用的前台窗口。
