# 游戏可动资产与运行时消费

制作角色以外的交互道具、载具机械、武器工具、植被、柔性物或可破坏资产，以及把任何绑定输出给游戏引擎时，先读这一份。一切设计从「运行时谁来消费、怎么驱动」倒推，按需选用最轻表示。

## 表示阶梯：按用途挑最省力的方案

先问清资产要给谁用（动画、玩法物理、渲染材质还是多系统协同），再从轻到重选表示：

1. **静态网格与对象变换**：固定件、纯平移旋转的门盖/旋钮/盆栽，直接设原点、父子层级和变换即可。
2. **材质顶点位移（WPO）与实例参数**：远景植被、草片和成片灌木的风摆，靠顶点色写入高度、枝权重与实例相位，单株成本极低。
3. **刚性层级或刚性单骨权**：多活动件联动的武器、载具、机械臂与机关，既可用对象层级，也可装在同一骨架下用刚性单骨权便于单资产动画与挂点管理。
4. **骨骼蒙皮与形态键**：需要弯折变形的近景树木主枝、弓臂、软管、角色躯体和软包袋。
5. **顶点动画纹理（VAT）与缓存**：大批量固定循环动作（远景树林、预制破碎动画），把离线求值烘焙成静态网格加纹理或缓存。
6. **物理约束与运行时组件**：可推开的物理门、车辆悬挂轮地、运行时缆绳组件或可交互碎块，交由对应引擎物理/玩法组件接管，并在 DCC 侧备好准确枢轴与简化碰撞体。

## 六类游戏可动资产制作要点

### 1. 交互道具与可动建筑（门、抽屉、宝箱、电梯、机关）

- **建准局部坐标系与枢轴**：铰链门绕真实铰链线转动，抽屉沿真实滑轨平移。枢轴可通过对象原点、骨头、Empty 或父逆矩阵共同表达，核清本地/父级/世界空间与移动父级（如船上或电梯上的门）。
- **厘清复合链与状态切换**：双开门、折叠门、把手锁扣与门上小门先画出相对运动关系；明确开启、关闭、锁定、卡住与中途反向接续的状态写者，区分动画控制、物理推门与受控混合。
- **独立核查承载与碰撞**：移动平台与阻挡门除了核对视觉位置，还要确认实际碰撞体速度同步与低 LOD 下的交互节点保留。

### 2. 车辆、载具与工业机械

- **分离物理轴与骨长轴**：Blender 骨长轴是局部 Y，而轮轴、舵面铰链或液压杆的物理转轴可落在任意校准好的局部轴上；先校验完整局部坐标系、行程限位与真实运动轨迹，再配刚性或软域权重。
- **区分开链与闭环机构**：轮式车把车体、转向轴、轮心滚动与悬挂分层；双叉臂、四连杆和液压推杆属于闭环结构，逐一验证两端闭合与可达范围，保持硬连杆刚性定长。
- **分开视觉、物理与碰撞层**：可见轮、物理射线/胶囊轮、车身阻挡碰撞与软胎/防尘套各司其职；履带按镜头和预算在材质滚动、路径件、骨链或物理链间选型。

### 3. 武器、手持工具与持握设备

- **先写挂点合同**：明确模型原点、主手握持参考、副手接触点、背/腰挂点和功能挂点（枪口、瞄具、抛壳口、搭箭点）的相对位置与归属，区分共享骨架 Socket 与单网格专用偏移。
- **分域处理刚柔部件**：枪栓、弹匣、扳机走刚性活动件；背带、弓臂和弓弦按柔性路径和拉距分别制作与验证。制作弓弦时先明确弓梢、握把与搭箭点几何，按目标拉距检查弦身拉直与弓臂弯曲协调。
- **按相机与玩法组织 1P/3P**：第一人称与第三人称按镜头裁切、握持接触和动画预算决定共用或分立表示，把视图层穿模和真实世界碰撞分开排查。

### 4. 植被（树、灌木、草与藤蔓）

- **按镜头距离和互动分层**：近景英雄树或可攀爬树干用主干/主枝/叶簇骨链，远景树林与大片草地优先静态网格配材质风（WPO）或 VAT，藤蔓按单端或双端锚定曲线骨链处理。
- **规范风通道与层次衰减**：走材质风时在顶点属性清晰写入根部高度遮罩、枝权重、同枝相干相位和叶片边缘衰减，按粗干低频、细枝高频分级调参，并在导入后核对通道极性。
- **分离视觉变形与玩法碰撞**：树干胶囊、可攀爬枝条碰撞和角色触碰触发器单独维护；大幅 WPO 或骨动画同步检查剔除包围盒（Bounds）扩展与阴影覆盖。

### 5. 柔性非角色资产（绳缆、软管、铁链、旗帘、软袋）

- **先定端点、长度与截面**：写清固定端、自由端与滑动端、静置长度、允许伸缩比例及抗扁截面要求；硬接头与柔性段分域过渡。
- **看清工具边界**：Spline IK 重点核对链长与缩放模式；B-Bone 分段弯曲导出前转为目标支持的实体分段骨、形态键或表面缓存；Cloth 区分固定点（Pin）、缝合（Sewing）、压力与碰撞集合；铁链按需选择关节约束近似或复合网格碰撞以保留环孔互锁。

### 6. 可破坏物与装配体

- **按目标选破坏层级**：表面破损贴花、设计缝拆卸掉件、预切块固定破碎动画、以及运行时刚体聚类支撑失效，各自对应不同的拓扑与物理管线。
- **规划状态交接**：完整态切换到受损或碎块态时，同步交接可见网格、断面材质、速度、附件和碰撞所有权，避免旧完整体和新碎块同时残留双碰撞。改变网格拓扑后同步更新或迁移原有权重与缓存索引。

## 运行时消费与跨引擎交接清单

把 Blender 资产交给 Unreal、Unity、Godot 或其他实时引擎前，逐项核对下面六条消费合同：

1. **高保真源与导出候选分离**：在 Blender 保留完整的控制器、约束、驱动与修改器源工程；导出时按目标引擎支持的子集（骨骼 TRS、形态键、缓存或 VAT）产出独立候选，保留采样前后对比并在真实目标读取器里回放验收。
2. **明确动画、玩法与物理写者**：多个系统共同作用于角色或载具时，明确优先级、混合顺序、切换帧速度交接与碰撞切换，让每个属性的写入方有清晰归属。
3. **核准 Root Motion 消费模式**：分清原地动作（In-Place）配速度曲线由脚本推进，还是由根骨驱动移动组件（以及不同移动模式下是否应用重力与 Z 轴位移），把视觉骨架根、渲染器根骨和玩法碰撞胶囊根一一对应清楚。
4. **保护功能挂点免受 LOD 删骨影响**：没有蒙皮权重的挂点骨和玩法参考骨同样参与运行时消费。在 Unity 中通过 `Extra Transforms to Expose` 保留外部访问节点，在 Unreal 中按需设置 Socket 挂点归属与 `Force Always Animated`，并在最低目标 LOD 实测换手与挂件位置。
5. **按目标平台核对权重上限与包围盒**：分别核查导入权重裁剪阈值、运行时每顶点影响数上限（如 4 权或自定义上限）、渲染器 Bounds 与离屏更新行为，确认减面、删骨与权重重归一后关节轮廓仍满足要求。
6. **精确记录动作槽与烘焙范围**：导出 glTF/FBX 时核清当前 Blender 版本的 Action、Slot 与 NLA 合并模式，记录绑定姿态、帧率与起止帧；确认由骨驱动的形态键和多对象同步动画在脱离原工程会话后依然正常播放。
