# 分类与名称决策

先采用当前项目规则；新项目的随包基线见[资产标准](asset-standard.md)第3—6节。本文件解释执行方法，不替代当前用户规则。

## 分类看可复用单元

- 先确认用户要管理文件包还是可复用数据块。角色 Collection 连同必需骨架是一个组合资产时，不把每个 Mesh 自动登记为独立资产。
- 同一个 blend 中独立可用的角色、材质、节点组可分别建记录。背景图片、压缩包、Substance 工程等记录为文件角色/配套资源，不能仅按扩展名强行标为 Blender 资产。
- `type/category` 使用 STANDARD 第3节的类型表。例如模型 `MOD → Models/...`；几何节点 `GEO → Nodes/Geometry/...`；材质 `MAT → Materials/...`。分类取决于交付的实际用途，不仅是宿主数据块的技术类型。
- 已有历史 `Geometry/Retopology`、中文 Catalog 等保留原值。若要采用新规范路径，先列“原分类→拟分类→依据”映射，再对范围内记录落实；不把历史差异当损坏，也不顺便重写整个树。
- 选择一个主要分类；风格、功能、对象题材等用标签补充，来源和许可使用独立字段。对复合或含混对象保留候选与理由，只询问会改变资产边界/后续使用的关键歧义。
- 标签如 `feature:rigged`、`engine:cycles` 须有实际证据；作者/来源不从英文名、中文名或 UAL 目录推断。用户对全库“大多自制”的描述不能转成逐文件作者确认。
- 用户明确指定风格标签时，可将本次指令作为标签依据并记录；没有矛盾证据时不再次要求确认，也不把普通标签编辑升级为发布验收。不要把用户指定标签表述成已独立验证的视觉或功能结论。
- CLI `asset.prepare edit` 的 tags 是全量替换：读取现有标签，计算保留+新增−明确删除，提交完整结果，避免只传新增项导致旧标签丢失。
- 历史 `classification_lifecycle` 是自由文本，不能直接写入规范的 `lifecycle` 枚举。已有明确 lifecycle 保留；需要转换时按具体角色/用途列映射，缺乏依据则待确认，不统一改成 published。

## 名称有不同层次

| 层次 | 操作原则 |
| --- | --- |
| 原包/已有文件名 | 保留，记录为 `source.original_name`；明确授权改名才做逐项迁移。 |
| 中文显示名 | 可用于人类检索，不必跟物理文件名相同。 |
| 数据块名 | 检查共享 users、链接/override、引用及驱动中的字符串路径。不可把全场景同名串全局替换。 |
| 新发布文件名 | 使用 `<TYPE>_<Subject>_v<NNN>[_<Variant>][_LOD<N>].blend`。 |
| Catalog 名与路径 | 表达分类，保持 UUID；不因为文件更名就重建 Catalog。 |

发布例子：`MOD_SofaChair_v001_Oak_LOD0.blend`、`GEO_ArrayOnCurve_v001.blend`。主题推荐 ASCII PascalCase；已有中文显示名保留，不机械音译原资产。LOD 是同一资产的细节级别，不是不同设计或版本。

版本至少三位，从 v001 开始。先按 asset_id 查已有记录和发布历史，再选更高版本；文件名检查器不能替代此查询。不同可独立使用的变体可分配新资产 ID 并关联 parent_asset_id，不能仅凭同名或 SHA 推定同一资产。

纹理新名遵循 STANDARD 第4节；保留 UDIM/序列关系，批次覆盖全部相关成员并同步节点路径。未知用途的纹理不要猜成 BaseColor 或 NormalGL。Map 类型、色彩空间和法线方向是独立属性。

## 新发布候选名检查器

`scripts/check_names.py` 使用 Python 标准库，输入 UTF-8 JSON：

```json
{
  "directory": "D:/ExampleAssetLibrary/Working",
  "names": [
    "MOD_SofaChair_v001_Oak_LOD0.blend",
    "GEO_ArrayOnCurve_v001.blend"
  ]
}
```

- 将示例 `directory` 换为本次授权的目标平台绝对路径，可以尚不存在；它是检查目标，不会被创建。
- 检查 Windows 非法字符/设备名/尾随字符、发布格式、v000、同批大小写冲突，以及目标目录现有文件/目录的大小写冲突。拒绝用子目录、绝对文件名或 `..` 绕过单文件名输入。
- 主题未采用 ASCII PascalCase 时仅提示建议；不会把推荐命名风格升级为全部旧资产的硬约束。
- stdout 为结构化 JSON；退出0表示这些名称检查通过，退出2表示有阻止项/输入失败。`ok` 仅限名称预检，不是发布许可或变更授权。
- 只读取该目录直接子项，不遍历全库、不改名、不迁移、不读取 blend、不写输出。用工具保存结果到新批次时注意退出码。
- 检查与实际创建之间状态可能变化，提交前仍检查源 SHA 与目标冲突。已有资产的拟新发布副本名称可以预检；原包改名规则、复杂纹理/UDIM名和数据块名不能由该检查器决定。

## 交付范围

分类规划表至少提供：目标文件+数据块身份/已有asset_id、当前分类、拟分类、标签增删、命名层次、旧新名称、证据、未决项。明确本批是“建议/管理记录已更新/工作副本已验证/已提交库”的哪一步，不把草稿当实际完成。

资产正式记录可用[随包模板](../assets/templates/asset-record.json)，文件角色分类保留原表结构。空数组表示已确认没有，null 表示尚未采集；不要为通过校验把未知依赖写成空数组。
