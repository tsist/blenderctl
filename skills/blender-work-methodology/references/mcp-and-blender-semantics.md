# 现场窗口、MCP 与 Blender 数据要点

处理正在打开的 Blender 窗口，或者排查网格、变换、节点里的隐蔽怪象时查这里。

## 现场窗口怎么接

1. **优先走各插件的 live / session 入口。** 用户在窗口里手调了材质、相机、几何节点、绑定或剪辑时间线时，用对应专项入口（如 `material handoff-live`、`camera session-live`、`geometry session-live`、`rigging-workflow session-live`、`compositing session-live`、`video inspect-live`）读取当前状态，落成带指纹的可恢复工作副本后再往下做。
2. **Blender Lab MCP 留在 Codex 里做观察和短小试验。** 需要快速看一眼当前打开的场景结构，或者跑几行短小代码验证一个想法时可以用它，用字典返回结构化结果。跑之前先读当前场景名、活动对象和脏状态，确认连的是对的窗口。
3. **正式修改与交付一律回到公共 CLI。** 把现场确认的结果另存到明确路径，通过 `blenderctl` 保存、校验依赖并另起进程冷重开，保证交付文件脱离当前窗口也能完整复现。同一份工程一次只让一个入口写，换手前先存盘再重新读取。

## Blender 里最容易踩的五个数据细节

- **分清对象（Object）和数据块（Mesh / Material / Action / NodeGroup）。** 几个零件共用同一个网格或材质时，改数据块会牵连所有使用者。动手前先看引用数，要单改一件就先独立复制一份数据块。
- **看准坐标系与变换。** 核对位置和尺寸用世界矩阵 `matrix_world`，留意父子逆矩阵、旋转模式（欧拉还是四元数）与负缩放。对已经绑好骨骼或带关键帧的对象保持原有变换结构，改网格尺寸进编辑模式或修改器里做。
- **区分控制笼与求值后的最终网格。** 挂着细分、布尔、阵列或缩裹修改器时，视口看到的和渲染算出来的可能设了不同级别。检查穿插、烘焙法线和导出几何前，看清当前读的是原始控制笼、视口求值还是渲染求值。
- **改完网格记得刷新依赖图。** 编辑模式里用 `bmesh` 改点线面并写回网格，改完数据块或自定义属性后触发依赖图更新，下游工具才能读到新状态。
- **靠稳定标识找节点和插槽。** 用节点的 `bl_idname`、插槽的英文 `identifier` 和真实数据引用定位，避开会随界面语言变化的显示名或会自动加 `.001` 的重名。
