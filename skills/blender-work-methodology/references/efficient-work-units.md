# 批量执行、封装时机与恢复

当一项制作需要横向对比多组参数、批量处理一批对象，或者某一步耗时很长需要稳妥续跑时查这里。单步小改直接在工作副本上快改快看就行。

## 什么时候值得封装成插件和 CLI

先按 AGENTS.md 的采用阶梯选最现成的工具：原生功能或项目已有工具够用就直接做；成熟开源插件能干就拿来用；优质教程里有标准步骤就照着做。

只有当一段多步操作**已经被作品验证有效，而且后面还要在好几件作品里反复跑**时，才把它收进插件逻辑并交给 CLI 调度：

- **插件**负责把连续几步领域操作串起来，让界面按钮和后台命令调同一份核心代码。
- **CLI**负责锁死输入文件指纹、建独立作业目录、跑批量对比、记日志回执并支持中断续跑。
- **代理**负责定制作目标、调用原生生图准备贴图参考、看渲出来的画面做判断。

需要新建插件、新命令族或大功能时，先向用户说清现成方案差在哪、能为哪些作品省多少工夫、大概要花多少精力维护，用户点头后再动手。

## 一次提交前备齐五样东西

跑批量对比（如 `material study`、物理参数扫描、多机位预览）前，先把输入收拢齐，一次拿回足够做决定的对照图：

1. **基准文件与指纹**：源 `.blend`、外部贴图或缓存的绝对路径与小写 SHA256。
2. **精确作用目标**：对象名、材质槽、UV 层或骨骼组，核对过共用数据块的影响范围。
3. **少量拉开差距的候选**：挑三五个真正有代表性的参数档位，固定住相机、灯光、渲染引擎和随机种子，保证看出来的是参数本身的差别。
4. **能拍到问题点的机位**：先用一个小样确认机位和光线真能照出你想调的那处细节（比如斜侧光看拉丝高光、特写看接缝），再铺开跑候选。
5. **专属输出目录**：每个批次用独立的 `work/audit/<batch>//jobs`，长报告落盘保存，终端里用 `--compact` 拿精简摘要和文件路径。

## 看结果与下一轮调整

拿到返回后先看诊断提示（有没有参数被上游贴图盖住、图层没开或插槽未连），再并排看同机位对照图。先在小范围选定优胜方案，再放到整件作品的多视角和换光环境下复查。

## 长作业等待与中断恢复

- **用有界等待代替反复轮询**：提交长作业后运行 `blenderctl.ps1 --jobs-dir <目录> --compact job wait <job_id> --wait-seconds 30`，一次等到终态或拿到当前跑到第几个候选。还在跑就继续等，避免重复提交同一份活。
- **按原回执精准续跑**：流水线中断用同一个 `--jobs-dir` 跑 `pipeline resume <job_id>`；事务中断用同一个 `--transactions-dir` 跑 `transaction status` 或 `recover`；单步作业失败留着原请求和日志，修好输入后从源副本重新提交。
- **只重算受影响的下游**：上游改了一个零件的 UV，就只重跑这个零件的贴图导出和预览，其余已经验收通过的部件原样复用。
