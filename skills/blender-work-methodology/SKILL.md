# Blender 工作方法论

## 最高指导：任何时候先考虑插件与CLI协作

每项实际Blender工作首先评估：能否借助适用插件，把有关联的多步操作封装为可检查、可恢复的一次工作单元，由CLI调度完成。优先复用现有插件/接口，再考虑适配或开发；参考确认、阶段预览和实际验收仍是工作单元的边界。具体选择、职责和恢复要求读取[插件与CLI工作单元](references/plugin-cli-work-units.md)。

此包保留该工作优先级；用户当前明确目标优先。单步不适用时说明判断，安装/开发不是每次任务的完成条件。

负责决定“先解决什么、为什么这样做、何时继续、凭什么完成”。具体操作从当前 Blender CLI 技能、MCP 工具 Schema 和实际版本取得，不在这里复制命令手册。

## 次级指导：让每次工作单元提供足够的信息与进展

在完成插件与CLI适用性判断后，提前准备明确目标、输入/资源身份、必要参数、有限候选、观察条件及恢复点；一次取得基线、变化、诊断、当前阶段、成功/失败范围和产物引用，先依据这些信息决策，再提交有理由的下一轮。长任务通过有界等待读取原作业；复用须核对指纹与SHA。不要把等待中的作业重新提交，也不要反复微调已被贴图覆盖或未连接的参数。具体组织与计量读取[完整工作单元与效率](references/efficient-work-units.md)。

此指导低于插件/CLI协作优先级，不能削减来源、快照、实际观察与交付验证；少调用、总耗时和作品质量分别判断。

本轮保留当前判断、冻结输入、已读合同身份、差异和下一检查点；详细证据留本批文件，宿主WM可用时按真实taskId记录，按需回读。输入、版本、外部状态或用户反馈改变时重新取证。先安排能看清关键缺陷的低成本观察，在请求最终质量反馈前备齐工程、验证摘要与交付说明，再用真实反馈完成必要收尾。具体边界见[效率章节](references/efficient-work-units.md)。

公开技能包0.2.0（2026-10-06正式修订）补充按需回读、关键观察前移和交付收尾组织；最高与次级指导的优先级保持。工具构建器、扩展诊断和全链路遥测仍为待开发候选；六项candidate、零validated领域方法保持。历史工程证据未发布，本修订尚未运行验证总体提速，不晋升普遍速度或美术保证。

装配案例A分件参考流程曾因最终外观偏离参考被用户否定。后续修订保留参考冻结、递增装配、造型对照和双验收；装配案例A v004整体获用户基本认可，但车座曲面与踏板厚度仍被指出问题，v005相应几何和UV复验是单案例证据，不能晋升为通用制作保证。

复杂流线或有厚度的细分外壳出现波纹、端部布线或贴图风险时，读取[复杂曲面控制网格与UV](references/methods/complex-surface.md)。该条从车座实战提取，仍为单案例candidate，不把四边面数或特定细分设置当通用配方。

## 复杂机械细化与联动入口（0.20.0）

已有机构继续增加硬表面细节、链条/软管/驾驶区/支承结构时，读取[复杂机械接口驱动细化](references/methods/mechanical-interface-detailing.md)。机械案例B叉车V002–V037提供接口采样、原始四边布线、真实三角接触、联动求值与变更范围回归的反例；新增条目保持candidate。运动检查同步区分离散与连续、包含与表面相交、区域接触与整对豁免；案例尺寸不作通用默认。当前六candidate、零validated。

## 材质制作阶段入口

**调用注释（2026-10-04）**：进入PBR阶段必须读取材质技能的完整规范。其硬规则要求所需空间图层/复杂遮罩原生生图优先，原生工具实际受阻时才回退可用生图技能，简单渐变/数学依赖遮罩可用Blender。插件+CLI负责多步组装和验证；插件内程序纹理不能替代已指定的生图来源。赤陶v008基本验收、青花瓷三表面用户验收及工具0.54/插件0.7的有界能力分别留证，其他材料/引擎/通道能力按后续实测增加。

开始材料参考分析、表面分层、着色节点、贴图或材质修复时，读取 [Blender材质制作技能](../blender-material-authoring/SKILL.md)（`blender-material-authoring`）。PBR是该技能的子章节，由它路由到参考、通道、CLI/MCP和验收细节；方法论只负责阶段判断，不另建PBR技能或复制材质配方。

进入实际上材质前确认所需几何/映射起点；异常来自轮廓、厚度或平滑法线时先返回相应建模检查。材质技能现行规则与案例成熟度分别记录，旧退役配方不恢复。

## 图像尺寸与会话预览（强制）

本包沿用保守图像预算作为操作约束，适用于参考、贴图、诊断与预览；它不是服务端限额或某次会话故障的根因声明。

- **生成一律不超过 2K**：本技能中 2K 明确定义为最长边 ≤ 2048 像素（宽、高均 ≤ 2048），保持所需比例；禁止默认生成 4K/8K 或先生成大图再缩小来满足生成上限。调用前设置工具实际支持的尺寸参数，并在提示词中注明上限；仅提示词写“2K”不算尺寸验证。生成器不能保证尺寸时明确能力限制；输出必须本地核对实际宽高，超限先隔离并缩小后才可传入会话或作为工作图使用，不声称原始生成已合规。
- **查看或上传前先本地检查**：读取实际宽高、格式及文件字节数，再决定是否调用图像查看、图像编辑参考上传、内联展示或把图交给子代理。不得先把大原图传入模型再检查，也不依赖工具自动缩放或页面显示尺寸作为防护；不输出图像 Base64。
- **大参考图先做独立压缩预览**：原图和冻结 SHA 保持不变，按比例缩小到最长边 ≤ 2048；通常先用 1280–1600 像素查看整体。会话预览另设单图 ≤ 2 MiB 的保守操作预算（不是服务端官方限额）；即使像素合规，文件超预算也需本地重新编码或继续缩小。普通照片/渲染预览可用高质量 JPEG；透明图、线稿、文字图按需要使用 PNG，避免压缩损伤判读。记录原图→预览的路径、实际尺寸、字节数和 SHA，核对输出可解码后只传预览。
- **预览不覆盖生产数据**：原始数据与色彩语义保持不变，仅生成供查看的独立可视化副本；禁止把有损预览替换为生产数据。现有高分辨率源资产不因本规则被覆写、重冻结或批量降质。
- **细节用局部图，控制总负载**：需要原尺寸判读时在本地裁取关键区域，每张仍遵守上述尺寸与字节预算，记录裁切坐标；不以缩略图代替细节验收。对照拼图合成后也要重新检查整体尺寸与字节数。先逐张查看，确需并排才少量分批，禁止一次塞入整套大图。
- **可恢复再上传**：开始图像传输前把工程/结果保存到明确路径，WM 记录当前阶段、待验图片和下一步。遇到图像上传超时或会话异常，不重复发送原始大图；改用更小预览、单张加载并保留故障记录。文件存在或压缩成功不代表视觉验收通过。

## 按需使用

- 多阶段制作、复杂修改或反复修复：使用下面的工作循环；需要保存实践证据时读取[实践记录模板](references/practice-record.md)。
- 单步小改：简化为“目标变化 → 执行 → 对照结果”，仍按实际影响核对目标、共享引用和恢复条件；简化记录不豁免必要保护。没有可复用发现时不写完整复盘、不改技能，出现下述触发信号时再进入改进协议。
- 选择已有经验时读取[方法索引](references/method-index.md)，只加载匹配本次输入、用途和证据范围的条目。
- 本次出现路线调整、质量失误、可复用发现、反例或用户纠正时，交付前读取[自我改进协议](references/self-improvement.md)，判断是否需要修订。没有新证据可以明确记为“不改”。

建筑外观建模需要从设计图定尺寸、开洞、搭接或组织重复构件时，读取[基础建筑硬表面建模章节](references/architecture-basics.md)；它汇总建筑案例A/建筑案例B/C的可复查经验与未验边界，不代替具体建筑规格。

载具、机械等由独立零件构成的硬表面对象，从参考制作阶段起读取[分件参考链](references/methods/part-reference-chain.md)（v3 修订版）：五级参考整体冻结后才建模；一致性检验清单在效果图生成后立即制定；建模期禁材质只用视口色区分部件；每件递增组装查穿插/分离；造型对照 pass 后才上材质；最终渲染按清单逐条对照效果图验收。装配案例A 两次反例：v1 跳过部件级参考单清单生成 68 个对象（挡泥板零厚度、车灯比例错误）；v2 参考未冻结、清单未先立、造型未确认就材质入库（渲染与效果图天差地别，用户判不合格）。

## 工作循环

### 1. 从交付反推问题

先执行最高指导的插件/CLI适用性判断，将本轮输入、连续操作、输出与检查点组织成工作单元，再安排下列制作循环。

将用户目标压缩成一句可观察的结果，分开记录：必须达到的结果、不可损坏的内容、可自由选择的实现。只收集会改变路线的尺寸、用途、帧域、画面、编辑性、性能与输出要求；文件里能查到的信息自行读取。

只询问影响正确性且无法查明的关键缺失信息；已授权范围内的一般制作选择可说明假设后推进，不把可选参数逐项变成确认门槛。

把验收依据区分为用户明确要求、可测事实、参考图支持的视觉判断和暂定假设。视觉任务说明从什么相机或视角判断；动画与模拟说明要观察哪些时刻和运动关系。不要把审美偏好包装成技术事实。

### 2. 建立可信起点

确认工作对象来自当前会话还是磁盘文件，以及目标内容、非目标内容和依赖范围。先获得足够理解目标的数据与预览，再决定路线；不做无关全场景扫描。

记录能回到起点的工作副本或检查点，以及用来前后对照的证据。CLI 与 MCP 换入口时使用明确、持久的快照；不能把磁盘副本当成用户未保存的当前场景。

只读检查可以先进行；会危及未保存编辑的重要修改、打开其他文件或跨入口交接前，先保护当前状态。检查点使用已授权范围内不冲突的路径；已有授权足够时直接推进，不因建立新副本重复询问。

### 3. 优先消除决定成败的不确定性

选择最可能导致整体返工的问题先做小样，说明预期观察及不成立时的替代路线。例如画面任务先确认构图和大形，变形任务先看极端姿态，模拟任务先验证决定效果的动态关系；这些是选择示例，不是所有任务必须走的阶段。

必要时比较两条可行路线，依据交付用途、可编辑性、输入质量、运行成本与恢复成本取舍。不要为了沿用熟悉工具改变用户的目标。预算与时限未给出时先用有界预览摸清成本，不擅自降低最终约定质量。

### 4. 用观察推动迭代

每轮围绕一个主要判断推进：**当前问题 → 工作假设 → 最小改动 → 实际观察 → 下一决策**。可以合并强耦合改动，但说明哪些效果无法单独归因。

先解决影响全局的关系，再投入依赖它们的细节。出现明显偏差时回到原因所在阶段，不用增加细节掩盖比例、结构、动作或构图问题。保留足够的前后对照，避免只凭最新画面判断改善。

在开始高成本渲染、长烘焙、破坏性转换或大量重复处理前，先用代表样本检查最关键假设；覆盖范围由用途和风险决定，不机械规定样本数量。

参考驱动的视觉制作：先明确采用图中的主视角，尽早匹配相机、轮廓、屋面/墙面/木作的大块明暗与关键连接。固定相机和光照比较画面迭代；再另做环境变化测试。参考差异清单仍有明显项时回到对应阶段，不以棋盘格、节点或渲染成功抵消。详见[参考一致性关口](references/methods/reference-fidelity.md)。

### 5. 按交付用途验收

将“操作执行成功”“作品达到目标”“方法可迁移”分别判断。检查本次变化及可能受影响的非目标内容；保存后按需要独立重开或由目标读取器验证。

| 交付侧重 | 验收要回答的问题 |
|---|---|
| 静态画面、材质与灯光 | 实际输出在约定构图、光照和色彩环境下是否达到目标？ |
| 可编辑模型与程序化结构 | 轮廓、比例和结构是否满足用途，关键后续编辑是否仍成立？ |
| 骨骼与动画 | 关键和必要中间状态是否保持运动关系与变形质量？ |
| 模拟、毛发与时序结果 | 缓存及重放是否可靠，观察范围是否足以支持所声称的质量？ |
| 交换与交付 | 目标读取器中保留了哪些内容，依赖是否可取得，有哪些损失？ |

验收记录使用 `pass / fail / not_run / not_applicable`，附证据或原因。技术检查、实际视觉观察、用户审美反馈分别记录；未看到输出就不能宣布视觉通过，采样通过不能扩成全帧保证。

用户尚未反馈时明确注明；只有事先约定必须由用户确认的关口才等待反馈，其余可按已完成的验收交付，不虚称用户认可。

### 6. 交付并关闭学习循环

交付文件、必要依赖、实际预览和简短变更说明；准确写出限制。再判断本次是否产生可复用的方法变化，而不是只记录使用了什么按钮。

按自我改进协议把观察转成有适用条件的候选；经过验证才更新默认建议。向用户简述本次沉淀了什么、尚不能推广什么。技能改进服务于交付，不以等待经验晋升为由拖延已完成作品。

## 操作层衔接

按任务选择一个入口或组合使用；需要渲染不意味着必须由 MCP 切到 CLI。入口取舍依据当前状态与实际能力，不把组合使用本身当成流程要求。

| 当前需要 | 操作入口 |
|---|---|
| 连续多步领域工作 | 优先适用插件封装操作，由CLI调度与验证；先读最高指导，必要时适配/开发 |
| 材料参考、表面分层、着色节点、贴图与材质验收 | 读取 [blender-material-authoring](../blender-material-authoring/SKILL.md)，PBR从其子章节进入；实际执行按CLI/MCP路由 |
| 已保存文件、结构化批处理、渲染、交换及恢复流程 | 读取可用的 `blender-cli` 技能，按实际帮助和契约执行 |
| 当前场景探索、上下文相关编辑与实时观察 | 使用 Blender MCP，先核对连接身份、文件、场景及 Schema |
| 两种入口交替 | 明确哪份状态是当前输入，持久保存后交接，避免并发写入 |
| 命名、Catalog、编目、入库或迁移 | 使用`blender-asset-manager` 技能与当前项目资产规范 |
| 现有入口缺能力 | 明确缺口，在已授权范围选择最小实现与验证；工具缺口不等于目标不可做 |

操作失败依照项目恢复规则定位；不把具体参数故障写成普适制作禁令。具体技巧进入相应操作技能或技术文档，这里只保留它改变工作决策的条件与证据入口。
