# Linux candidate publication (Blender 5.3)
Invoke `blenderctl transaction publish --job-id ID --source /original/input.blend --output /private/export/new.blend`. Omit source only for a source-free job. Use `status` instead of `publish` for observation. The pinned Linux runtime is selected automatically. No network, rendering, production overwrite, cached authorization, external dependency relocation, or Windows transaction compatibility.

The absolute output parent must already exist, be owned by this Unix user and have mode 0700, with no symlink ancestors. Destination must be new (or this exact previously committed transaction). The backend outcome, source, manifest, candidate and request are checked; a fresh offline Blender opens the staged bytes, with auto-execution disabled. Linked libraries and unbundled asset references are refused; the built-in factory brush chooser is not an external production dependency. This check is a local scene/dependency reopen, not a render, asset fidelity inspection, plugin reconstruction or an isolation boundary against malicious Blender files. Use the local, already-trusted job store only.

Publish uses a small hidden directory beside the final file, with a single prepared journal for each output filename. A hard-link creation is the atomic no-replace commit. Status is read-only. Repeating the identical publish reconciles prepared or already committed work; a different job/file/digest cannot borrow the receipt. A prior crash during staging can leave an unpublished stage; previously unprepared remnants are not automatically discarded and are bounded. Do not move the output directory, job roots, or backend receipts during the transaction. Retain the receipt for status/replay; do not sync the hidden directory to public destinations. This is local-filesystem-only; it is not a distributed transaction or authenticated provenance against another process controlling the same user account.

The original transaction test harness was not included in this snapshot. Rerun a real end-to-end publish on a new disposable working copy before operational use.
